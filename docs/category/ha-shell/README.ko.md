# `ha-shell` 카테고리

*[English](README.md) · 한국어*

`ha-shell` 은 master/slave 페어를 겨눈 `shell` task 다 — CTP 는 이것을 `ha_shell.conf` 와 함께
`shell` 로, `HA/shell` 트리 위에서 돌린다. **독립된 task 가 아니고**, 그것이 여기서 다른 무엇보다
먼저 알아야 할 사실이다: **케이스는 shell 케이스**이며, 같은 규칙으로 발견되고 같은 판정
헬퍼로 판정된다.

HA 라는 말을 쓰는 다른 하나는 [`ha_repl`](../ha-repl/README.ko.md) 이고, 둘은 오라클 말고는
공유하는 것이 거의 없다. 한 줄로 요약한 차이:

| | **`ha-shell`** | **[`ha_repl`](../ha-repl/README.ko.md)** |
|---|---|---|
| 무엇을 묻는가 | 복제가 *이것* 을 견디는가 — 멈춘 노드, 재시작된 서비스, 다시 만든 슬레이브 | 복제가 *이 SQL* 을 올바르게 옮기는가 |
| 누가 토폴로지를 움직이는가 | 케이스가. 373 중 263 이 그렇게 한다 | 아무도. 구조상 정상 상태 |
| 누가 페어를 만드는가 | 케이스가 `make_ha.sh` 를 불러서 | 러너가 |
| 코퍼스 모양 | 셸 스크립트 | 변환된 `sql` 코퍼스 |

| | |
|---|---|
| **[2. 케이스 쓰기](02-writing-a-case.ko.md)** | 두 경로, 배치, verb 들, 그리고 동결된 코퍼스가 어기는 세 규칙 |

형제 카테고리들이 가진 다른 번호 문서들 — 런이 어떻게 도는가, 돌리기, 설정, 실패가 무엇을
남기는가 — 은 **쓰이지 않았다.** 그것들이 설명할 부분이 만들어지지 않았기 때문이다.
[§ 두 경로](02-writing-a-case.ko.md#the-two-paths)가 정확히 어느 것인지 말한다.

구현 전 설계 — 여기 인용된 모든 측정값과, HA 테스팅이 establish 해야 하는 일곱 속성 — 는
[`../../project/design/module-ha.md`](../../project/design/module-ha.md) 다.

## 이 스위트는 무엇을 위한 것인가

**정지해 있는 토폴로지 위에서 복제가 행을 옮긴다는 것을 establish 한다. 그 토폴로지가 교란된
뒤도 포함해서.** 이것은 실재하고 쓸모 있는 일이며, 그것을 분명히 말해두는 것이 중요하다.
코퍼스가 마치 다른 일을 하는 것처럼 보이기 때문이다.

373 케이스 중 263 이 노드를 멈춘다 — `cubrid hb stop`, `cubrid service stop`, `kill -9`. 그러고
나서 하는 일은 **행이 그래도 도착했는지** 묻는 것이다: 115 가 그 뒤 데이터 동일성을 단언하고,
22 가 전이가 거쳐 간 상태들을 보고, **4 가 시간을 잰다.** 그러니 그 움직임은 정상 상태 비교를
위한 전제 조건이지 주제인 경우는 거의 없다.

여기서 케이스를 쓰는 사람에게 따라오는 결론이 둘이다:

- **교란 자체를 조사하고 싶다면** — 분할, split brain, 자기 파라미터에 대해 측정되는 switchover
  — 그것은 다른 축이고, fault verb 가 필요하며,
  [`module-ha.md`](../../project/design/module-ha.md) §4 에 **group B** 로 명세돼 있다. `kill -9`
  로 근사하려 하지 마라. **사라진** 노드와 **살아 있으면서 상대가 사라졌다고 믿는** 노드는 엔진의
  서로 다른 코드 경로이고, split brain 이 사는 곳은 두 번째뿐이다.
- **셋업 전이가 끝나기 전에 비교가 돌면, 그 비교는 아무것도 측정하지 않으면서** 초록 판정으로
  그렇게 말한다. [규칙 1](02-writing-a-case.ko.md#1-never-sleep-to-synchronise) 이 그것에 관한
  것이고, 기존 코퍼스에서 가장 흔한 결함이다.

## 오라클, 그리고 그것이 왜 좋은 부분인가

케이스는 마스터에 쓰고, 같은 행을 두 노드에서 각각 파일로 읽어 비교한다. 373 중 169 가
`compare_result_between_files` 를 통해 판정에 이르고, 313 이 `csql` 로 읽는다.

**답 파일이 없다.** 엔진의 출력 형식이 바뀌어도 낡는 것이 없고, 다시 기록할 것도 없다. 비교는
**같은 빌드를 돌리는 두 노드 사이**에서 일어나며, 그것이 HA 테스팅의 유지 비용을 싸게 만든다 —
그리고 `ha_repl` 이 같은 오라클에 **독립적으로** 도달했다는 것이 그것이 옳다는 가장 좋은
논거다.

이것을 지켜라. 기대 출력 파일을 들여오는 새 케이스는 이 스위트를 가질 만한 물건으로 만드는 바로
그 성질을 포기하는 것이다.
